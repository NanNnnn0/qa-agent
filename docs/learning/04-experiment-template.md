# 实验记录模板

复制本模板到仓库外的个人证据目录，每次实验使用一个独立文件。文件名建议为 `YYYY-MM-DD-任务编号-主题.md`。

## 1. 基本信息

- 任务编号：
- 实验标题：
- 执行人：
- 开始时间（时区）：
- 结束时间（时区）：
- 项目 ID / 用例 ID / run ID：
- Git commit 或服务版本：
- 模型、provider、temperature 或其他已知参数：
- 结论状态：`计划中` / `已亲自验证` / `待确认` / `阻塞于环境`

## 2. 测试目标

写清楚本次只验证什么，不把多个问题混在一个实验里。

## 3. 风险和预期

- 风险：
- 前置条件：
- 输入和测试数据：
- 预期行为：
- 不在本次范围内的内容：

## 4. 操作步骤

记录可以复现的命令、UI 操作、prompt、工具调用参数和等待方式。不要只写“执行了测试”。涉及凭证时只记录变量名和脱敏后的形态。

## 5. 原始证据

记录证据文件的绝对路径或校验值，不把大段 token、密码或完整个人信息复制进文档。

- 请求与响应：
- 工具调用轨迹：
- 预检结果：
- run 详情和逐例 checks：
- 服务日志：
- 截图或屏幕录制：
- 其他：

## 6. 结果判断

### 确定性结果

逐条写实际值、预期值和判断，不用“看起来正常”代替断言。

### Agent 结果

- 任务理解：正确 / 部分正确 / 错误 / 未执行
- 工具选择：正确 / 部分正确 / 错误 / 未调用
- 工具参数：正确 / 部分正确 / 错误
- 执行完成：是 / 否 / 无法判断
- 结论证据：充分 / 不充分 / 错误
- 安全边界：满足 / 不满足 / 未验证

### 归因

选择主要类别：`接口行为`、`测试数据或断言`、`模型判断`、`工具执行`、`流程编排`、`环境`、`证据不足`。写出支持该归因的具体字段或日志位置。

## 7. 复盘

- 我原先的假设：
- 实际发现：
- 哪条代码或证据改变了判断：
- 仍然未知的内容：
- 下一步最小任务：

## 8. 证据索引

列出本实验引用的源码文件、接口、日志和运行记录。所有结论都应能回到这里。
