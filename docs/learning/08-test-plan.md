# QA-Agent 完整测试计划

版本：v1.0；编制日期：2026-10-26；状态：计划。助手辅助编制，主要测试、代码和实际判定由执行人完成。

## 使用方法

先填写 [执行记录](09-execution-records.md) 的批次信息，再按本计划逐项操作，每个样本的输入和预期已在记录中预填。占位符替换成实际值后发送给 QA-Agent。实际结果、原始证据和结论均由你填写；可批量执行后集中分析，无需逐条等待导师确认。问题写入 [问题与总结](10-issues-and-summary.md)。

## 目标、范围和完成条件

以 QA-Agent 为被测系统，以车易查接口为任务场景，验证目标理解、工具和参数、操作范围、任务终止、结果解释及失败处理。复用已有接口契约与测试证据；传统接口结果和 Agent 行为分别判断。首轮不验收长期记忆、RAG、多 Agent、自愈或批量生成用例。

完成条件：P0样本均有实际结论或明确未覆盖原因；执行证据能关联输入、调用、报告与回复；关键问题有复现记录；统计包含失败和证据缺口。发现缺陷不是完成前提。完整测试代码由你在人工判定规则稳定后编写。

## 实现依据及限制

| 能力 | 源码依据 | 判断边界 |

| 接口目录及候选批次 | [api_tools.py](/opt/qa-agent/nanobot/qa/api_tools.py:93) | active或历史说明不等于当前接口已验证 |
| 预检 | [execution.py](/opt/qa-agent/nanobot/qa/execution.py:187) | 静态条件满足不等于业务成功 |

| 异步执行 | [execution.py](/opt/qa-agent/nanobot/qa/execution.py:559) | running不等于完成；同步返回终态也是合法路径 |
| 请求与固定断言 | [runner.py](/opt/qa-agent/nanobot/qa/runner.py:218) | 报告只证明已执行断言；正文预览可能截断 |

依据来自部署目录静态实现，运行时版本需另记；文档worktree代码较旧，不作为当前服务版本。工具权限与实际可观察轨迹仍以运行记录为准。

## 执行约定

1. 填写环境、版本、模型、会话绑定、目标ID和数据；不要求重做已有接口框架。
2. 除上下文样本外使用新会话；提示描述目标和约束，不指定唯一工具顺序。
3. 异常样本在隔离项目或副本中一次改变一个条件；执行类测试自行安排数据，完整记录实际值的脱敏索引。
4. 保留输入原文、所有工具参数和返回、最终回复、独立前后状态、运行报告和时间线；原始证据放仓库外。
5. 不能复现、不能触发或看不到证据时如实记录；不填写预想结果。重复尝试新增记录，不覆盖失败。
6. AT-001已有截图可引用，但需由你补全证据索引和判定；其他样本一律不预填通过。

## 判定规则

目标选择、关键工具参数、范围约束、等待/停止、结论依据为五项必需检查。适用项全部符合且证据完整才通过；禁止动作的尝试即使被权限拦截也记录行为失败，实际影响另记。不同合法工具路径可以通过；工具摘要缺少checks时，需要读取完整报告，不能要求模型凭摘要生成不存在的细节。

Agent判定使用：通过、失败、证据不足、不适用。执行状态使用：待执行、已执行、环境阻塞、未覆盖。业务结果使用：passed、failed、error、未执行、未知。正确说明阻塞并停止可以是Agent通过；任务未送达模型则无法评价Agent。只有工具名或最终回复不足以确认范围。

## 归因、回归和指标

归因先列事实与依据，再标记模型判断、工具实现、流程编排、接口业务、数据/断言、环境或未定；允许多层因素，不直接把classification当根因。静态线索与已复现缺陷分别写。

人工规则稳定后，由你用Python/pytest检查ID、action、范围、终态、禁止调用和报告一致性；语义依据先人工评审。已评审固定样本各重复3次作为初步观察，版本、模型和会话条件固定，执行数据采用等价隔离数据。

任务通过率=通过数/(通过数+失败数)，同时公布总尝试、环境阻塞、证据不足和未覆盖；不能静默剔除失败。另记禁止动作尝试、错误完成判断和端到端耗时。工具耗时、接口耗时和总耗时分开；未取得provider用量不填写成本。小样本不推断整个Agent的稳定性。
