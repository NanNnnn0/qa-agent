# 学习路线

## 总目标

最终能够用真实证据回答四个问题：车易查接口本身怎样测试；QA-Agent 怎样把测试任务转成工具动作；一次失败发生在接口、工具、模型还是编排环节；怎样把这些结果做成可重复的评估和可信的项目经历。

## 知识塔

### 第一层：项目和证据

学习项目结构、服务入口、数据目录、数据库、运行前提和证据规则。完成标志是能画出一条从用户输入到最终结果的流程，并能指出每个结论的依据位置。

### 第二层：传统接口测试

复习请求方法、参数、鉴权、响应结构、业务规则、状态变化、测试数据和断言设计。完成标志是能独立为车易查注册接口建立一条可复现基线，并解释每条断言对应的风险。

### 第三层：模型与 Agent 机制

理解消息、提示词、工具描述、工具参数、模型调用循环、工具结果回传、上下文和停止条件。完成标志是能从调用日志中还原一次 Agent 任务，而不是只看最终回答。

### 第四层：Agent 新增测试对象

测试任务理解、项目和用例选择、工具选择、参数正确性、结果解释、完成判断、错误恢复和安全边界。完成标志是能把一次失败归到模型判断、工具执行、固定编排、接口行为或环境问题中的一个主要类别，并说明证据。

### 第五层：评估和测试开发

区分确定性断言、任务级评估、人工评审和重复运行，学习记录成功率、耗时、工具调用、成本和失败类型的统计口径。完成标志是学习者亲自编写少量有意义的评估代码或数据处理脚本。

### 第六层：工程化和职业表达

学习版本固定、数据隔离、日志脱敏、回归、缺陷记录和结果复盘。完成标志是能用真实案例说明个人贡献、发现的问题、证据和局限，不把项目已有能力或导师辅助工作写成个人完成。

## 阶段路线

| 阶段 | 重点 | 主要产物 | 进入下一阶段的条件 |
|---|---|---|---|
| S0 | 项目地图与环境核对 | 项目地图、环境清单 | 能解释入口、组件和未验证项 |
| S1 | 车易查接口基线 | 一条注册接口的原始请求响应和判断 | 有安全测试数据和明确预期依据 |
| S2 | 固定 QA 执行器 | 预检记录、运行报告、断言对照表 | 能解释平台报告不等于业务正确 |
| S3 | 主 Agent 工具链 | 一次 Agent 调用轨迹和最终产物 | 能还原模型每次工具选择和参数 |
| S4 | Agent 异常与边界 | 少量高价值异常实验记录 | 能区分五类失败来源 |
| S5 | 任务级评估 | 评估样本、评分规则、重复运行记录 | 指标有分母、范围和证据 |
| S6 | 测试开发与回归 | 学习者编写的 pytest/评估脚本 | 脚本能重复运行，失败有诊断信息 |
| S7 | 复盘与面试素材 | 项目总结、缺陷记录、简历草稿 | 每个亮点都能指向原始证据 |

## 每轮学习节奏

每轮只做一个小任务：先说明测试什么和风险，再由学习者操作，保留原始证据，最后一起分析归因并更新知识卡片。完成一个任务不代表整个能力已验证；尤其 Agent 的一次成功不能代表稳定成功。

## 暂不提前假设的能力

在车易查项目上尚未证明自动规划、长期记忆、自动恢复、多 Agent 闭环或稳定的任务级成功率。只有在对应实验完成并保留轨迹后，才能把这些能力从“代码或提示词中出现”升级为“实际验证”。
