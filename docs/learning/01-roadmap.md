# QA-Agent 测试实施路线

以下是测试工作顺序，不是课程。每轮从一个实际任务开始，由你运行、记录和判断；出现知识缺口时再解释相关概念。

| 工作项 | 要完成的测试工作 | 产物 | 完成标准 |
|---|---|---|---|
| A1 任务执行基线 | 先测只读预检任务，核对目标、工具参数、范围和结论 | 一条任务样本与调用轨迹 | 你能依据独立事实判断 Agent 做对或做错 |
| A2 最小执行闭环 | 在运行条件满足后，让它只执行一条车易查用例 | 任务记录、run 详情和断言对照 | 执行范围正确，最终结论与实际结果一致 |
| A3 异常与结果误判 | 逐个覆盖用例不可执行、工具错误、运行未完成等实际分支 | 异常记录、可复现的问题或风险 | 区分模型、工具、编排、接口和环境原因 |
| A4 指令与数据边界 | 检查只读限制、项目范围、数据与凭证处理 | 范围越界与脱敏检查记录 | 没有未获允许的动作，结论不泄露敏感数据 |
| A5 样本回归与测试开发 | 固定少量任务，重复运行，你编写轨迹和结果检查脚本 | 任务集、pytest 或评估脚本、原始统计表 | 自动判断适合断言的部分，保留人工判定理由 |
| A6 总结与简历素材 | 汇总覆盖范围、实际问题、回归结果和个人贡献 | 测试总结、证据索引、简历草稿 | 每条成果可解释、可追溯，没有编造提升指标 |

## 基线怎样建立

优先复用你已有的车易查请求、响应和接口测试记录。我们只核对它们是否对应当前环境、数据和用例，不把再做一轮传统接口测试当作开始 Agent 测试的前提。

第一次从不发业务请求的预检任务开始。后续真实执行前，再核实 base_url、ready 状态、注册数据隔离和原始响应采集。注册会产生用户数据，重复对照应使用等价且相互独立的数据，不能要求同一手机号连续两次都注册成功。

## 范围怎样扩大

先有一条你亲自完成的记录，再扩展同义表达、输入不完整、工具失败和重复运行。接受满足目标的不同合法工具路径，不强制模型逐字复现某条调用顺序。

任务规划、长期记忆、多 Agent、RAG 不作为已存在能力纳入验收。只有确认实际实现、可用入口和预期后，才单独增加测试范围。

## 交付节奏

一次任务只说明测试什么、风险、前提、输入、操作、预期和证据。你提交实际结果后，我帮助分析和补充下一条任务；不预生成全套用例，也不提前填写报告结论。
