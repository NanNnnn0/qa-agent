# 学习与测试任务清单

任务按依赖顺序排列。每个任务由学习者亲自完成主要操作，导师只在任务开始前解释目标，在任务结束后帮助分析。

## S0 项目和环境

### L0-01 建立项目地图

测试什么：确认车易查项目、QA-Agent 服务、入口、用例、运行记录和存储之间的关系。为什么：没有组件边界，后续无法归因。操作：阅读 [02-project-map.md](02-project-map.md) 对应源码并画一页自己的流程图。证据：文件路径、代码行号、自己的流程图。完成条件：能说明模型做什么、固定代码做什么、哪些尚未验证。

### L0-02 核对运行前提

测试什么：核对实际项目 ID、base_url、用例状态、模型配置和目标端口。为什么：避免把环境阻塞误报成接口缺陷。操作：只读检查工作台或 API，保存脱敏结果，不发送注册请求。证据：时间、项目字段、端口和配置可用性记录。完成条件：明确写出“满足”“不满足”或“待确认”。

## S1 传统接口基线

### L1-01 建立注册接口契约表

测试什么：方法、路径、请求字段、字段类型、响应结构、业务码和数据前提。为什么：Agent 测试也必须有可判断的任务级预期。操作：对照当前接口资料、用例和真实需求，列出一致项与冲突项。证据：契约表和来源链接。完成条件：每个关键预期都有来源或标记为待确认。

### L1-02 手工验证一条安全基线

测试什么：注册成功或一个不会污染共享数据的异常路径。为什么：先知道接口实际行为，才能评估平台和 Agent。操作：由学习者用 requests 或 Postman 执行一次，使用隔离数据，保存脱敏请求和响应。证据：命令、时间、环境、请求、响应、判断。完成条件：结果可由另一人按记录复现。

### L1-03 设计最小 pytest 断言

测试什么：把手工基线转成少量有意义的确定性断言。为什么：保留传统接口测试能力，并建立后续对照组。操作：学习者编写并执行最小脚本，断言状态码、业务码和关键字段，不断言随机 token 的具体值。证据：代码、执行输出、依赖版本。完成条件：失败时能定位到具体断言。

## S2 固定 QA 执行器

### L2-01 检查用例能否进入 ready

测试什么：车易查用例的状态、请求、断言、变量和追溯前提。为什么：执行器会拒绝未 ready 用例，状态本身是平台契约。操作：调用只读查询或工作台查看，必要时记录阻塞原因，不擅自改业务数据。证据：用例 JSON/YAML、预检结果。完成条件：解释每个 blocker 的来源。

### L2-02 对照固定执行结果

测试什么：同一请求在学习者 pytest 与 QA-Agent 固定执行器中的结果是否一致。为什么：验证“平台通过”检查的是哪些内容。操作：在安全前提满足后运行单条用例，比较请求、断言、报告和日志。证据：两侧输出、run_id、用例 revision、响应预览。完成条件：能解释差异，而不是只比较 passed/failed。

## S3 主 Agent 工具调用

### L3-01 让主 Agent 完成受限任务

测试什么：模型能否理解“只验证一个注册用例”，选择正确项目和工具并停在正确位置。为什么：这是最小 Agent 闭环。操作：给出明确范围、成功条件和禁止事项，记录完整工具调用轨迹。证据：原始 prompt、每次 tool name/参数/结果、最终消息、run_id。完成条件：能逐步还原模型判断和代码执行。

### L3-02 检查错误参数处理

测试什么：项目 ID、用例 ID、action、case_ids 等输入错误时，Agent 是否识别并纠正。为什么：Agent 经常失败在工具参数而不是接口本身。操作：一次只改变一个参数，记录模型是否重试、重试是否合理。证据：调用轨迹和最终状态。完成条件：区分工具参数错误、模型纠错和环境错误。

## S4 异常、恢复和安全

### L4-01 预检阻塞任务

测试什么：未 ready 用例、缺少 base_url、未解析变量或服务不可达时的任务行为。为什么：不能把“未执行”误报为“接口失败”。操作：选择一个可控阻塞条件，先预检再观察 Agent 结论。证据：预检 JSON、是否发出 HTTP 请求、最终回复。完成条件：结论明确标为 blocked 或 needs_review，并说明原因。

### L4-02 结果判断边界

测试什么：断言成功但业务预期不足、HTTP 200 但字段错误、接口返回错误码时 Agent 是否正确解释。为什么：HTTP 200、工具成功和模型回复合理都不能单独证明任务完成。操作：使用已有用例或安全的模拟结果，比较断言、响应和最终结论。证据：逐条 checks、响应、结论。完成条件：每个结论都能指向具体证据。

### L4-03 数据和凭证安全

测试什么：日志、报告和模型回复是否泄露手机号、密码、token。为什么：接口测试平台的测试数据和 Agent 上下文都可能产生泄露。操作：使用脱敏数据执行一次，检查运行报告、日志和最终消息。证据：脱敏前后字段清单、报告位置。完成条件：明确记录实际遮蔽范围和残留风险。

## S5 评估和测试开发

### L5-01 建立任务级评分规则

测试什么：任务是否选对目标、调用是否正确、执行是否完成、结论是否有证据、风险是否说明。为什么：最终文本质量不能代表任务成功。操作：为 3 至 5 个固定任务定义二值或分级评分，并先人工评审样本。证据：评分表、样本、评审理由。完成条件：不同人按规则评分能得到接近结果。

### L5-02 重复运行和指标采集

测试什么：同一任务多次运行的成功率、工具调用次数、耗时和失败类别。为什么：Agent 输出有随机性，单次成功没有代表性。操作：固定模型、提示词、项目、用例和超时，记录每次 run。证据：原始运行表和统计脚本。完成条件：指标包含分母、样本范围、时间和适用限制。

### L5-03 学习者编写小型评估脚本

测试什么：从日志或运行结果自动提取关键字段并生成摘要。为什么：体现测试开发能力。操作：由学习者自己用 Python/pytest 编写，不复制整套平台实现。证据：脚本、输入样本、输出和失败诊断。完成条件：脚本对至少一个失败样本给出有用原因。

## S6 复盘和职业表达

### L6-01 缺陷与评估记录

测试什么：把接口缺陷、模型错误、工具失败、编排问题和环境问题分别记录。为什么：这是面试中最能体现判断力的部分。操作：选择已实际验证的 1 至 3 个问题填写缺陷记录。证据：重现步骤、日志、最小输入、预期/实际。完成条件：不把待确认线索写成缺陷。

### L6-02 项目总结和简历素材

测试什么：整理个人贡献、项目已有能力、辅助工作和未完成内容。为什么：避免夸大 Agent 能力或编造指标。操作：每条简历表述绑定一个实验记录和证据路径。证据：项目总结、简历草稿、证据索引。完成条件：面试时能现场解释一条完整案例。
