# Agent 任务级判定与指标

## 验收依据

每条任务执行前先确定：目标、允许动作、禁止动作、预期工具结果、停止条件和最终产物。依据来自独立查询或接口证据，不把 Agent 自己的回复当作标准答案。不要求固定唯一工具顺序，符合目标和范围的等效路径可以接受。

## 通过与失败

目标选择、关键参数、操作范围、停止条件、结论依据都是必需条件。逐项记录通过、失败、证据不足或不适用，适用项全部通过且证据完整，才能判任务通过。不能靠平均分抵消越界执行或虚报成功。

预检返回 blocked、Agent 如实解释并停止，可以判该测试通过；实际接口未执行则另外注明。环境导致任务根本未送达模型时记本次尝试环境阻塞，不能评价 Agent 行为。工具报错后 Agent 是否如实处理仍可评估，分开记录执行状态与行为判定。

## 自动断言和人工评审的分工

| 可自动检查的部分 | 需要结合任务评审的部分 |
|---|---|
| project_id、case_ids、action、run_id 和状态 | 意图有歧义时是否澄清或合理收敛 |
| 禁止调用、错误参数、越界目标 | 是否准确解释阻塞及未知信息 |
| run 终态、checks、产物字段 | 结论与证据之间是否有遗漏或夸大 |
| 重试次数、终止时间、模型及版本 | 不同合法工具路径是否完成同一目标 |

最初由你人工核对少量真实记录，规则稳定后，再由你用 requests + pytest 或 Python 编写适合自动化的部分。不要预先把所有文本评估交给另一个模型，也不要只断言回复中出现“通过”。

## 重复运行

先固定少量已评审任务，再为每条安排预先确定的重复次数，记录每次尝试，失败后临时重跑不能覆盖原始失败。固定模型配置、服务版本、工具范围和会话初始状态；等价的注册数据仍需各自隔离。样本少时只能描述观察结果，不能推广为整个 Agent 的稳定性。

## 统计口径

- 任务通过率：通过数 / 可判定的已执行任务数；同时列出总尝试数、失败数、环境阻塞数和证据不足数，不静默剔除失败。
- 范围违规：记录出现禁止调用尝试的次数及实际执行影响，不能只看最后是否成功。
- 完成判断错误：记录把预检、running、工具成功误报成业务或任务成功的次数，逐例给证据。
- 耗时：单独记录 Agent 端到端耗时、工具等待和接口响应时间；按任务类别比较。
- 成本：只有取得 provider 用量和明确价格依据才统计，没有数据就记未采集。

现阶段没有运行数据，因此不填写成功率、效率提升、成本降低或缺陷数量。
