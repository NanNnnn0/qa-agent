# QA-Agent 测试工作包

## 工作目标

你作为测试工程师，使用车易查接口任务作为场景，验证 QA-Agent 是否可靠完成测试工作。交付物是测试方案、任务样本、执行证据、问题记录、回归脚本和项目总结。概念只在测试需要时解释，不设置先学完概念、画完架构再开始测试的条件。

本目录沿用已有路径，内容已替代此前的课程式安排。测试对象是 QA-Agent；车易查接口及其已有测试结果用于提供任务背景和判断依据。你已经完成的接口工作优先复用，只补影响 Agent 结果判断的证据缺口。

## 和传统接口测试的区别

| 同一个场景 | 传统接口测试的主要判断 | Agent 新增的判断 |
|---|---|---|
| 让它检查注册用例 | 请求和断言是否合法 | 是否理解目标、选对项目和用例、遵守只检查不执行的要求 |
| 让它执行一条用例 | 请求是否成功、业务结果是否符合契约 | 是否限制执行范围、传对工具参数、等到最终状态 |
| 让它解释失败 | HTTP、业务码、数据和状态为什么异常 | 是否依据工具结果解释，是否把环境阻塞误报成接口缺陷 |
| 重复同一任务 | 固定条件下接口结果是否稳定 | 模型选择和结论是否稳定，失败是否可归因和复现 |

接口返回成功，只能说明接口层面的某些检查通过。Agent 任务成功还需要目标正确、动作符合范围、结果判断有据。反之，正确识别阻塞并停止，也可能是一次通过的 Agent 测试。

## 协作和证据

你负责主要测试执行、样本扩展、测试代码、原始证据和第一版判断；我负责分析实现、提供必要示例、检查预期与归因、协助整理。主要测试不由我代跑，整套测试代码不由我预生成。

状态分开记录：计划中、代码已实现、实际已验证、尚未验证、环境阻塞。当前仅完成静态分析和方案修订；没有你本轮的 Agent 测试结果，不能写成个人已完成成果。原始日志和响应留在仓库外，分享时脱敏。
