# Agent 测试学习资料包

这套资料以车易查接口为业务案例，以 `/opt/qa-agent` 中的 QA-Agent 为被研究的 Agent 系统，目标是让学习者亲自完成从接口基线、固定执行器验证、Agent 工具调用到任务级评估的完整过程。

## 使用方式

先读 [学习路线](01-roadmap.md)，再按 [任务清单](03-task-backlog.md) 一次完成一个任务。每个任务完成后，把原始证据放在仓库外的个人证据目录，把结论填入 [实验记录模板](04-experiment-template.md)，最后更新 [进度与总任务总结](07-progress-summary.md)。

这不是一套可以一次性填完的测试报告。计划中的内容不能写成已完成结果，代码中存在的功能不能直接写成已验证功能，历史资料中的“实测”字样也不能替代本次实验。

## 状态标签

- `计划中`：已经设计，但还没有执行。
- `已读实现`：已经找到源码或文档依据，但没有完成实际运行验证。
- `已亲自验证`：学习者本人完成操作，并保留了可复现证据。
- `待确认`：有线索或历史记录，但当前证据不足。
- `阻塞于环境`：因服务、凭证、网络、数据或依赖不可用而无法判断产品行为。

## 角色边界

学习者负责主要测试操作、测试代码、证据收集和第一版结论；导师负责解释实现、设计小任务、检查判断逻辑和帮助归因。导师不代跑完整测试，不把没有执行过的结果写成通过，也不替学习者制造简历指标。

## 当前基线

本资料包的初始判断基于 2026-10-22 对 `/opt/qa-agent` 的静态阅读和运行状态观察。QA-Agent 服务和 QA 代码入口已经找到，车易查项目目录已有注册接口资料、测试点和 20 条迁移用例；车易查接口实际可达性、当前数据库项目配置、用例 ready 状态和 Agent 端到端成功率仍是待验证内容。
